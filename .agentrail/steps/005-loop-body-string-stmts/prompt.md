microgpt-mlpl bug (j): any string-valued statement inside a repeat / train / for body fails the whole loop with 'expected an array value, got a string' (print("abc") returns its arg; q = "abc"). while is fine. Cause: eval_blocks.rs eval_repeat (and eval_train) and eval_for.rs call .into_array() on EVERY body statement's value, not just the final one. Fix: evaluate non-final statements and discard their values; only the value the loop actually consumes needs to be an array -- train's per-step loss (final stmt), for's per-row capture (final stmt). repeat's own value: tolerate a non-array final statement (keep the last array / 0) rather than erroring. Where an array IS required, make the error name the construct, e.g. 'train: the body's last statement must be the step loss (a number), got a string'. TDD from their reproducer (../../softwarewrighter/microgpt-mlpl/docs/upstream-issues.md section j): repeat 1 { q = "abc"; 0 }, repeat 1 { print("abc"); 0 }, def u:f() { repeat 1 { q = "abc"; 0 }; 1 }, same for train and for. Also note their second complaint -- the error carried no line number -- and check whether loop-body errors lose the statement span; if a cheap span attach exists, do it, else queue in future-sagas-queue.
