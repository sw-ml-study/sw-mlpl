Step 009 pivoted from analyze-crate extraction to capability-trait foundation. Investigation showed every analyze file (model_clone, model_embed_table, ..., model_perturb) depends on Environment + EvalError + Value + crate::eval::eval_expr recursively -- extracting them without first establishing C+D capability traits would force a cycle back to mlpl-eval. Created components/mlpl-session/crates/mlpl-env-traits/ as a small foundation crate, seeded with HasModels (the simplest trait). mlpl-eval impls HasModels for Environment in env_trait_impls.rs. Sub-crates will now depend on the traits instead of &Environment, enabling unit tests against Mock impls that don't carry the full struct.
