Repro: open Paths -> pick any path -> click a lesson step -> click the Paths nav button -- it goes to the top picker (the walker position is gone). Root cause: apps/mlpl-web/src/mode_path.rs cb_path_open_lesson (line 28) and cb_path_run_demo (line 44) both call path_state.set(None) on navigation, clearing the saved walker position. (1) Drop the path_state.set(None) calls in cb_path_open_lesson + cb_path_run_demo so path_state survives navigation. (2) Render_modes.rs treats paths_active = path_state.is_some(), so leaving path_state set will erroneously show paths-mode on the lesson view -- introduce a new 'viewing-via-path' sub-state (e.g., add a from_path: bool to UiState, OR change paths_active to require BOTH path_state.is_some() AND !tutorial_active). The simpler fix is the latter: paths_active = path_state.is_some() && !tutorial_active. (3) Add a 'Back to path' link/button to the tutorial lesson header when path_state.is_some(). Clicking it should set tutorial_view/lesson_idx to None so the PathsView walker re-renders with the saved position. (4) Same affordance for the demo view if the user navigated to a demo via the path. (5) The Paths nav button (mode_select.rs cb_select_paths) currently does path_state.set(Some((None, 0))) when path_state is None; once the bug is fixed, that fallback still applies for cold starts but in-progress paths just toggle visibility. (6) Unit tests for the new flag transitions in app_hooks/mode_path. (7) Pages rebuild required.
