User report: in connect mode ':disp(g)' / ':disp g' say 'undefined variable: g' although g exists (server-side). Root cause: colon-prefixed lines are classified as inspect commands everywhere -- the client keeps them browser-local (where g does not exist) and the server shunts them to inspect. But ':name(...)' is a builtin-ref CALL expression, not a command. Fix: expression-shaped colon lines (^:[a-z_]+\() parse+eval as programs on both the server (parse_unless_command) and the client connect router; ':disp g' (not a call, not a command) gets a tailored hint naming the trichotomy.
